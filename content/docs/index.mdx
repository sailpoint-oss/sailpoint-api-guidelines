These guidelines are the rules SailPoint uses to design consistent, secure, and evolvable APIs. Use them when designing a new API, reviewing a pull request, or integrating against SailPoint APIs. The rules are the source of truth — every requirement, example, and anti-pattern lives in a rule.

## How to read a rule

Each rule has a stable kebab-case ID, a level badge, and a canonical example shown directly below the badge. Cite rules by ID in reviews and design docs, e.g. `[#define-a-standard-error-contract-in-openapi-problem-details]`.

Rules use RFC 2119 language:

- **MUST** — required.
- **SHOULD** — strongly recommended; exceptions need to be justified and documented.
- **MAY** — optional; use when it improves client experience or operational safety.
