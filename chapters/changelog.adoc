= Changelog

This change log only contains major changes made after October 2021.

Non-major changes are editorial-only changes or minor changes of existing guidelines, e.g. adding new error code.
Major changes are changes that come with additional obligations, or even change an existing guideline obligation.
The latter changes are additionally labeled with "Rule Change" here.

To see a list of all changes, please have a look at the https://github.com/sailpoint-oss/sailpoint-api-guidelines/commits/main[commit list in Github].

(Note that recent changes might be missing, as we update this list only occasionally,
 not with each pull request, to avoid merge commits.)

[[rule-changes]]
== Rule Changes

* `2026-11`: Aligned the guidelines with the rules that the API linter checks:
** Added <<401>>, <<403>>, <<405>>, <<406>>, <<407>> and <<408>>. The linter already checked these rules.
** Filled in <<225>> with the scope pattern `^[a-z]+:[a-z-]+:[a-z]+$`.
** <<151>>: listed the required response codes (2xx, 400, 401, 403, 429 and 500), and stated that they use the shared response files in `apis/shared/responses/`.
** <<326>>: changed the link to the error response object from the deprecated `v3/schemas/ErrorResponseDto.yaml` to `apis/shared/schemas/errorresponsedto.yaml`.
** <<159>>: every `GET` that returns an array must define `offset` and `limit`, and `limit` must define `minimum` and `maximum`.
** <<303>>: parameter descriptions must be at least 8 characters long.
** <<304>>: documented the example exemptions for nullable properties and for arrays with item examples.
** <<305>>: every operation must have a `summary`.
** <<317>>: a `required` list must not be empty.
** <<400>>: added the approved verbs `close`, `load`, `process`, `publish`, `reload` and `test` for POST, and `overwrite` for PUT.
** Added the Test icon to <<110>>, <<159>>, <<219>>, <<225>>, <<316>>, <<321>>, <<324>> and <<325>>, and removed it from <<189>>.
** <<110>>: a list operation must return an object with an `items` array. An existing list operation that returns an array turns off the rule with `x-sailpoint-lint-ignore`.
** <<154>>: filled in the collection format of query and header parameters.
** <<151>>: an operation with no parameters and no request body does not need a `400` response.
** <<310>>: a boolean in a PUT request body does not need a default.
** Retired <<176>> (problem JSON). Error responses use the format in <<326>>.
** Retired <<314>> (`Ref` suffix on reference objects), because it conflicts with the example in <<315>>.
